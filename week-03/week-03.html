Selectors

Oct 5, 2026 selectors switches checkboxes radio-buttons research spec micro-motion tone

Brief

Twelve components: four sets, each one switch, one checkbox and one radio button, each set expressing a tone. Tones can repeat across sets. Every design has to do its job. Each one gets a working prototype, with the versions tried along the way shown as its process.

Every component sits in a list, each row with a text label, the way the brief's examples do: a settings row with a switch, a list of meal extras with checkboxes, a language picker with radio buttons.

The spec

No Figma file this week: every prototype carries its own spec, in a section of the prototype page. At least spacing, font, font size and line height, the component's size, and every other property that shapes it, such as roundness and stroke width. The numbers are read from the same values the prototype runs on, so the spec cannot drift from the design.

Research

All three say yes or no to something. What differs is how many answers a list allows, and when the answer counts.

Read mainly against Apple's Toggles guidelines and Material 3's switch, checkbox and radio button pages, every tab of each: overview, specs, guidelines, accessibility. IBM's Carbon, one of the open systems on Design Systems' public list, is a third voice. Where they agree, it is a rule. Where they differ, it is room for a tone.

Three selectors

Which one, and where

Apple's guidelines say less about drawing these controls than about choosing between them, and Material agrees on almost every point. The choice decides the list each prototype sits in.

A switch lives in a list row

The row's own words are its label. Outside a list, iOS uses a button that changes its background instead, and macOS keeps switches out of toolbars.

Weight follows what it controls

A switch is heavier than a checkbox, so it suits a setting that matters or one that turns on a group. On the Mac, a regular switch leads and mini switches follow.

Settings with children are checkboxes

Checkboxes line up on their leading edge and indent to show what depends on what. A parent whose children disagree shows a dash, the mixed state.

Two to five, then a menu

Radio buttons come in sets of two to about five. Past that, the list swallows the screen. Both systems draw the line at five and switch to a menu.

One on/off is a checkbox

A tick reads faster than a lone dot. Use a pair of radio buttons only when each state needs its own name.

Side by side, evenly

Laid out in a row, every radio button gets the width of the longest label, so the gaps never wobble. Material would rather they were never in a row at all.

Switch, up close

Material draws the switch in dp, the numbers below. The on state is told twice: the handle crosses the track and it grows from 16 to 24 dp, so colour is never the only signal.

  1. Track52 × 32 dp, fully round. Off: a 2 dp outline and no fill.
  2. Handle16 dp off, 24 dp on, 28 dp while pressed. Always 24 when it carries an icon.
  3. Icon, optional16 dp. It has to mean on or off: a check and an X, never a moon or a pencil.
  4. State layerA 40 dp circle behind the handle on hover, focus and press.
  5. Target48 dp. Denser layouts may shrink it only when people ask for them.
SwitchHow it behaves
LabelInline and short, naming what the switch does when it is on. The label keeps its colour in both states.
EffectAt once, no Save. If it waits, it is not a switch.
KeyboardTab lands on the handle; Space or Enter flips it.
Screen readerReads the label, then “switch”. A vague label like “Photo album” gets a fuller accessible name: “Photo album access”.
Touch and pointerTap or drag grows the handle; hover grows the layer. The control shows it noticed before it changes.

Checkbox, up close

The smallest of the three, and the only one with a third state. Material 3 added indeterminate and error versions of every state.

  1. Container18 dp square, 2 dp corners, a 2 dp outline when empty.
  2. Icon18 dp, centred: a check for on, a dash for mixed.
  3. State layerA 40 dp circle on hover, focus and press.
  4. Target48 dp, and the label belongs to it: clicking the words ticks the box.
CheckboxHow it behaves
LabelOn the trailing side, scannable. In an editable checklist the box may stand alone.
GroupIf the set's relation isn't obvious, a heading introduces it, its baseline lined up with the first box.
EffectUsually when the form is sent. When a single box turns something on or off, it acts at once.
KeyboardTab to each box, Space ticks it. Material's own checkbox key table is copied from its chips page, so the WAI-ARIA pattern is the one to follow here.
Screen readerReads the label, then “checkbox, checked”. The accessible name is usually the visible label.

Radio buttons, up close

A radio button never stands alone: the group is the component. Each option needs its own label, because each is a different answer.

  1. Ring20 dp icon, drawn with a 2 dp stroke.
  2. Dot10 dp, only in the chosen one.
  3. State layerA 40 dp circle on hover, focus and press.
  4. Target48 dp, label included: the words choose too.
Radio buttonsHow they behave
LabelEvery option has its own, after the circle. The group's title names the group.
How manyTwo to five. More than that, and a drop-down saves room, at the cost of an extra tap and more thought.
EffectAt once, unless the group sits in a dialog or page that is saved.
KeyboardTab enters at the chosen one, or the first if none (Shift+Tab: the last). Arrows move and choose, wrapping from last to first. Space chooses and never clears.
Screen readerA “radio group” named by its title; each option read by its label.

What the motion teaches

Arrive slow, leave fast

Turning on eases into place and earns a look; turning off hurries away. Material's checkbox leaves in under half the time it arrives.

Travel says which way

The switch handle crosses the track, so where it ends is the answer. A small overshoot makes it feel thrown rather than placed.

Answer the press, not only the release

Held down, Material's handle swells to 28 in 100 ms; iOS stretches its knob into a pill. The control shows it felt the finger before anything changes.

Grow from where it lives

The radio dot swells out of the ring's centre; the checkbox fill pops up from 60%. Nothing slides in from somewhere else.

Colour cuts, shape moves

Colour changes in 50 to 67 ms, almost instantly. The time is spent on shape and position, which is where the eye follows the change.

Follow the finger

On iOS the knob can be dragged, and a spring picks up the finger's speed where the drag ends. With reduced motion on, the end states alone still have to read.

Speed is a tone, too

Carbon draws the same switch with the opposite temper. Its handle and track colour move together in 70 ms on an exit curve, with no overshoot: the switch is simply already there. Material spends 300 ms and lets the handle overshoot. Same job, two characters, so duration and curve belong to the tone, not only to the spec.

Rules the tone has to survive

The whole row is the target

Clicking the words flips the control too. Material draws an 18 dp box inside a 48 dp target: the drawing can be tiny, the hit area cannot.

The label stays put

“Wi-Fi” stays “Wi-Fi” whether it is on or off. The control carries the state; rewriting the words as it flips only makes people read twice.

Never colour alone

On and off must differ in shape or position too. Apple names three ways: add or remove a fill, show or hide a shape, change the mark inside. WCAG 1.4.1.

Edges you can see

The outline of an empty box or ring needs 3:1 contrast against what is behind it, off state included. WCAG 1.4.11. A new accent colour has to stand clear of the off state too.

A switch acts now

Flip it and the thing is already on. If a choice waits for Submit, it is a checkbox, not a switch.

One group, one stop

Tab lands on the chosen radio once; the arrow keys move the choice. Start with one chosen, or the group can never return to none.

When a row needs help

On the Mac a tooltip, which Apple calls a help tag, appears when the pointer rests on a control; in visionOS, when the eyes do. Touch has no hover, so on a phone the same sentence lives under the label instead. Atlassian suggests a tooltip to say what flipping a toggle will do, which is where week 2's tooltips meet these rows.

Explain the one being pointed at

Describe only the control the person is asking about, not its neighbours and not the bigger task around it.

Start with a verb, skip the name

Say what the control does, as an action: “Pause background updates”. The label already says “Low Data Mode”; repeating it wastes the space.

Sixty to seventy-five characters

A fragment, no articles. If a control needs more than that to explain, Apple's advice is to simplify the control, not lengthen the tip.

Sentence case, no full stop

Sentence case reads as plain speech. Leave off the closing full stop unless the rest of the product uses one.

Change with the state

A selector has two states, so its tip can have two sentences: each says what flipping it now will do.

Teach the strange by motion

Don't explain how a standard switch works. If a tone makes the control unfamiliar, orient people with animation, not a paragraph.

The row around it

The brief puts every control in a labelled list, so the row is part of the spec too. A baseline to depart from: a tone can move every number here, as long as the rules above still hold.
